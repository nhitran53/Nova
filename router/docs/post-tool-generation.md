# Post-tool-call generation scaffolding (2026-10-24, UNCOMMITTED, branch feat/router)

Status: scaffolding only. No real model is wired in. Every new policy value is a PLACEHOLDER pending human sign-off.
Research basis: `research/postcall-generation-2026-10-24.md` (sources labelled there; no Qwen/Mac measurements exist yet).

## 1. What was built
- `router/generation.py` (pure Python, no model deps):
  - `GenerationRequest` (frozen): turn_id, kind (`tool_result|grounded_answer|chitchat|confirmation`), route, user_text, tool, facts (verbatim tool_result data), `slots` (name -> `SlotSpec` kind/fmt/unit/required), code-computed tier `labels` (`<field>_tier` = `critical|warning|normal`, derived from the human-owned `sim_fields` thresholds; fields with no `sim_fields` entry get none), `allowed_numbers`, passages, `passage_numbers` mode, persona, `StyleLimits`, refusal codes, optional digit-masked history, deadline_ms. Built deterministically by `build_request(...)`.
  - `render_prompt(req)` -> chat messages (static system block first, per-turn context, `<utterance>` last); `render_prompt_text`, plus illustrative `output_json_schema` / `output_gbnf` helpers (never executed).
  - `Generator` Protocol (`generate(req) -> GenerationResult`; `stream` documented only), `FillerGenerator` (deterministic stub with scripted/forced-bad modes for tests), `LegacyLLMAdapter` (wraps old `llm_fn(text, prompt_policy, passages)`).
  - `postprocess(...)`: parse JSON -> refusal -> unknown/malformed slot -> missing required slot -> prose number scan (before fill) -> length -> action-claim / directive-verb / live-reading deny-lists -> slot fill -> `verify_numbers` backstop.
  - `run_generation(...)`: retry (max_attempts, one corrective line) then fallback; generator exceptions never retried. `deadline_ms` is enforced with a `time.monotonic()` wall clock (injectable `clock=`) as well as the generator-reported `latency_ms`; the outcome reports both (`latency_ms` reported, `wall_ms` measured). Model output over `generation.max_raw_chars` or too deeply nested to parse is a `parse_error` (retry/fallback), never an exception.
- `turn.py`: NO_TOOL chitchat and `call_llm` now go build_request -> generator -> postprocess -> `_speak`. Every line that is spoken, including the fixed replacement after a failed generation, is submitted to `_speak`; the rejected model text stays in `blocked_text` and `result["generation"]` (`replacement_verifier`, or `replacement_blocked_text` if even the replacement is refused). Tool-turn slot names must be unique across the tool_result data: a collision raises instead of silently picking one. `TurnHandler(generator=...)` injects a generator. Tool/confirmation turns keep template speech (llm_called False) but expose `result["generation"]` (mode `template_only`: request summary, prompt; the live request object is `TurnHandler.last_generation_request`, not part of the JSON-serializable result). Alerts build no request and never call a generator. New result key `generation` is additive.
- `turn_policy.json`: new `generation` section (existing values untouched). `demo_turn.py --fake`: shows request, prompt, raw output and verified line for tool, chitchat, grounded, forced-bad (retry -> fallback; retry -> success), exception, and alert turns.
- Tests: `tests/test_generation.py`; see the suite count in section 7 (428 before this work).

## 2. Why (key decisions)
- Tool and confirmation numbers never come from the model: it writes `{slot}` placeholders; code fills from `tool_result` using policy formats and appends units. The prompt hides tool values (names/kinds/labels only), so there is nothing to copy wrongly. The one exception is grounded answers under `passage_numbers="digits"` (the shipped default): the model may write numbers that are backed by a retrieved passage (checked by `verify_numbers`), with no unit or claim binding yet. `off` removes that exception. Magnitude is given only as tier labels (critical/warning/normal) computed from the existing `sim_fields` thresholds; there are no separate level bands.
- Templates remain the speech for tool routes (zero latency, already verified); the request is exposed so a model can later paraphrase non-safety acks. LLM is only for chitchat and grounded answers.
- Retry is bounded (2 attempts, deadline-aware); failures fall to known-good lines; `blocked_text` keeps the model text.
- Untrusted text (utterance, passages, history) is escaped and delimited.
- `postprocess` runs `verify_numbers` itself and `_speak` runs it again: defence in depth.
- `passage_numbers` default `digits` preserves current behaviour (nothing silently changed). `off` masks passage digits in the prompt and bans all prose numbers. `quote_span` is rejected at load ("documented but not built") rather than silently degraded.
- **Passage-number policy (user decision 2026-10-24, from the advisor recommendation):** `digits` stays the default, with two code-enforced additions (section 8). (1) Risk override: on a grounded `call_llm` turn, if the user text OR any retrieved passage hits `llm_scope.risk_terms`, the EFFECTIVE mode for that turn is `off` (`generation.risk_term_passage_override`, PLACEHOLDER, default true): passage digits are masked in the prompt, all prose numbers are banned, so the answer carries no document numbers and the model must refuse or answer without numbers. The turn is NOT diverted to a template, so manual lookups still work, just without numbers. (2) Attribution: in effective `digits` mode, code prepends `generation.attribution_prefix` (PLACEHOLDER, "According to the document,") to a grounded answer whose spoken text contains a passage number; never model-trusted, never doubled. `quote_span` stays rejected as unbuilt.
- **Directive verbs stay rejected for grounded answers** (a manual line like "return to..." is not read out as a model answer). Reading manuals verbatim will be a SEPARATE mode later; it is not built and not designed here.
- **`severity_tiers.spoken` removed** (user decision; the key was never read). Warnings are unchanged: `turn.py` speaks an alert only for a tier with `preempts_router: true` (critical); a warning-tier alert is only reported in `result["alerts"]`, never voiced as an alert (the separate fixed "Warning, oxygen margin is tight..." feasibility lines on navigation turns are template speech and are unaffected). Whether warnings should sometimes get audio is a future human decision. `uses_llm` is kept (the loader refuses a tier that both preempts the router and uses the LLM).

## 3. How to build off it
- **Plug in Qwen:** implement `Generator.generate(req)`: `render_prompt(req)` -> your runtime (llama-server / llama-cpp-python with GBNF from `output_gbnf(req)` or JSON schema; or MLX guided generation), disable thinking mode, temperature 0, `max_tokens` from `req.style`; return `GenerationResult(raw=<json string>, latency_ms=...)`. Pass via `TurnHandler(generator=...)`. Postprocess/verifier/fallback need no change. Measure TTFT and tok/s on the Mac first.
- **Retrieval:** inject `retriever(text)`; passages above the score threshold flow into `build_request(passages=...)` for grounded kind only.
- **New tool:** add a schema + function in `tools.py` (registry max 8, now 6), a template, and `generation.slot_kinds` entry (unique slot names; a collision raises) so slots derive automatically; a tier label appears automatically if the field is in `sim_fields`.
- **Streaming/TTS:** `stream` is a stub; `tts_fn` is still called once per turn.

## 4. Unbuilt
Real LLM and runtime choice; real retriever/documents; `quote_span`; streaming + sentence-level TTS and alert barge-in; real number verifier hardening (unit binding); eval set (~50 grounded questions with adversarial passages); grounded fallback is always `verifier_blocked` (`no_document` only via retrieval gate or model refusal); README not updated.

## 8. Risk-term override and attribution (2026-10-24, same uncommitted change)
- Code: `generation.risk_terms_in` (the same word-prefix matcher `turn.py` uses for NO_TOOL diversion), `passage_override`, `attribute_passage_numbers`; `build_request` applies the override, `TurnHandler._llm_reply` applies attribution after a successful generation and before `_speak` (so the verifier checks the final spoken line).
- Records: `GenerationRequest.passage_numbers` is the EFFECTIVE mode, `configured_passage_numbers` the policy value, `passage_override_reason` e.g. `risk term 'oxygen' in passage p2`; all three are in `GenerationRequest.summary()` and in `result["generation"]` (plus `passage_numbers`, `configured_passage_numbers`, `passage_override_reason`, `attribution_prefixed`; `result["generation"]["text"]` is the final spoken text).
- The override applies only to grounded requests whose configured mode is `digits`, and only when `risk_term_passage_override` is true. Matching is a word-prefix on lowercased text, so "pressurize" hits "pressure" and "o2" hits "o2 line"; terms come from the human-owned `llm_scope.risk_terms`.
- Attribution runs only when the final status is `ok`, the effective mode is `digits` and the filled text contains a spoken number; text already starting with the prefix (case-insensitive) is left alone; the first letter of the model text is lower-cased only when the second letter is lower-case. (Superseded by section 9: the prefix now counts toward `max_words`.)
- Known limits: a risk term missing from `risk_terms` (e.g. a synonym) is not caught; a number word in a passage ("twelve") is not a source in either mode; `digits` still has no unit/claim binding for non-risk topics.
- Tests: `tests/test_generation.py` section "risk-term passage-number override, attribution, severity_tiers.spoken removal"; demo: two extra grounded turns in `demo_turn.py --fake` (non-risk with attribution; risk term in the question forces `off`). Suite: 574 passed, 0 skipped.

## 9. Second review fixes (2026-10-24, same uncommitted change)
Each item has a regression test in `tests/test_generation.py` (section "second review fixes").
- Mask echo: in `off` mode (and in history) the prompt masks digits as `[number]`. A model reply with any square bracket (`[number]`, `[ Number ]`, a stray `[`) is now the violation `placeholder_in_prose` (a number violation: chitchat rejected for it speaks `verifier_blocked`), with its own corrective-retry hint. It applies in every mode.
- Verifier: `million`, `billion`, `trillion` are scale number words ("two million five hundred thousand" = 2500000); `twice`, `thrice`, `several` and the plural scales `hundreds`/`thousands`/`millions`/`billions`/`trillions` are vague-quantity words, fail-closed like `half` (unsupported unless the same word is in a source string). No shipped template or fixed line uses any of them (tested). `render_system` and the `vague_quantity_in_prose` hint name `twice`, `several`, `million`. Side effect, same as the existing `hundred`/`thousand`: "2 million" in a passage leaves the spoken word `million` (1000000) unsupported unless 1000000 is also in the sources, so such an answer is blocked (fail closed).
- Illustrative GBNF (`output_gbnf`): a sentence is 1..W pieces (a piece is a word or a slot, optionally followed by `, ; : -`, except the last piece before `. ? !`); sentences N and W come from `gbnf_limits(style)` (N = min(max_sentences, max_words), W = max_words // N), so the grammar cannot allow more than `style.max_words` words. It is stricter than `postprocess` (even split per sentence; the attribution prefix is not reserved). Tested structurally by translating the emitted rules to a regex; nothing runs llama.cpp.
- Verifier injection: `postprocess`/`run_generation` backstop uses `TurnHandler.verifier` (was the default `verify_numbers`); `_speak` remains the final gate (so an injected verifier now sees a successful line twice).
- Attribution: the prefix words count toward `max_words` (`too_many_words`, detail "including the attribution prefix") when code will add it; it is skipped when the text already starts with the prefix or a similar lead (`ATTRIBUTION_LEADS` = "according to").
- `result["generation"]` is JSON-serializable (`json.dumps` works): `request_object` was removed. The live request is `TurnHandler.last_generation_request` (reset each turn, `None` when no request was built); `demo_turn.py` uses it for the shadow run.
- New PLACEHOLDER: `generation.corrective_retry.hints.placeholder_in_prose` ("Do not write [number] or any text in square brackets; ..."); the `vague_quantity_in_prose` hint wording was extended with "twice or several".
- Unicode compatibility characters (review 2 P1): `postprocess` strips category-Cf characters (zero-width space/joiner, soft hyphen: `fi\u200bve` is `five`) and NFKC-normalizes the model text before any scan, so fullwidth `［number］` is caught; `〔〕`/`【】`-style brackets are listed in `BRACKETS`. Any non-ASCII Nd/No/Nl character (`²`, `⑫`, `½`, Arabic-Indic or fullwidth digits) is `digit_in_prose` in every mode, before normalization. `verifier.fold_text` does the same strip + NFKC and maps leftover numerals by `unicodedata.digit`/`numeric`, so `verify_numbers` reads them as numbers. The text kept in `blocked_text` is the normalized form.
- Review 3 P1s (invisible marks, homoglyphs, fractions) are closed structurally, with an allowlist instead of more blocklists:
  - Prose allowlist: after the Cf strip (zero-width space/joiner, soft hyphen, bidi marks are still silently removed) and BEFORE NFKC folding, `postprocess` rejects every character of the model `text` that is not printable ASCII (U+0020-U+007E) and not in `generation.allowed_extra_chars` with the new violation `non_ascii_in_prose` (a number violation, so a chitchat answer rejected for it speaks `verifier_blocked`). Whatever the Unicode category (combining marks such as U+034F and U+FE0F, Cyrillic/Greek homoglyphs in `f\u0456ve`, fullwidth letters, accents, other spaces, newline/tab, controls) it is rejected, so no folding rule has to anticipate a character. It fires in addition to the older specific codes (`number_word_in_prose`, `digit_in_prose`, `directive_verb`, ...) when they also apply, because the invisible marks are still folded away for those scans.
  - New PLACEHOLDER `generation.allowed_extra_chars` (required key, string; default `’‘“”–—`: curly apostrophe/quotes and en/em dash). The loader refuses digits, marks, spaces, controls, brackets and ASCII in it. New PLACEHOLDER hint `generation.corrective_retry.hints.non_ascii_in_prose` ("Use plain ASCII letters and punctuation only ...").
  - Verifier, fractions: `fold_text` replaces every vulgar fraction (any non-ASCII character with a non-integer `unicodedata.numeric`, or whose NFKC contains U+2044) and every fraction slash by `FRACTION_MARK` (U+2044) BEFORE NFKC, and drops the digits next to it. NFKC no longer turns `½` into the two numbers 1 and 2. In spoken text the mark is an unsupported number (`unsupported == ["fraction"]`, `ok` False); in a source it authorizes nothing (not 1, not 2, not 0.5), so `verify_numbers("The cycle takes 2 minutes.", ["The cycle takes ½ minute."])` fails. Fraction values are still not built.
  - Verifier, invisible marks: `fold_text` (used by `verify_numbers` for spoken text and sources, so the final `_speak` gate) also strips the Mn characters U+034F, U+180B-180D/180F, U+FE00-FE0F and U+E0100-E01EF, like Cf, so `fi\u034fve` is `five` and `re\u034fturn` is `return` there too. `strip_format_chars` stays Cf only (used by `postprocess` so that the allowlist still sees the Mn characters).
  - Behaviour changes: an answer with newline/tab is now rejected (the generator is meant to emit one line); the Unicode evasion tests that counted one violation per attempt now accept the extra `non_ascii_in_prose`; the pinned `[1.0, 2.0]` for `½` was replaced by the fail-closed expectations; `fold_text("\u2cfd")` (Coptic one half) is now the fraction mark, not "0.5".
- Review 4 fixes (tests: section "review4" in `tests/test_generation.py`):
  - `allowed_extra_chars` validation: the loader now accepts only non-ASCII characters of Unicode category Pd, Pi, Pf or Po (dashes, quotes, other punctuation; `EXTRA_CHAR_CATEGORIES`). Letters (so Cyrillic `і`, Greek `ο`, fullwidth letters), symbols (`™`, `€`), marks, numbers, separators, controls and every bracket (Ps/Pe and `BRACKETS`) are refused, so the setting can no longer re-open the homoglyph bypass. Shipped default unchanged.
  - Spelled ordinals: `ORDINAL_WORDS` (`fourth` ... `nineteenth`, `twentieth` ... `ninetieth`, `hundredth`, `thousandth`, `millionth`, `billionth`, `trillionth`, plus plural fractions such as `fifths`) are part of `VAGUE_QUANTITY_WORDS`: rejected in prose as `vague_quantity_in_prose` and unsupported in `verify_numbers` unless the same word is in a source string (so a passage that says "the fifth stage" can back the same word). Compounds (`twenty-first`) are already caught by their tens/number word. `first` and `second` are deliberately ALLOWED (common prose; `second` is also a unit of time); `third` was already a vague quantity word and stays one. No shipped template, fixed line or filler uses any of these (tested).
  - Split spellings (`split_token_in_prose`, new violation code and number violation): `postprocess` runs a detection-only pass (`_split_denied_word`) on the prose, never changing the text that is spoken. Letter runs separated by spaces, hyphens, underscores or a single dot are joined in windows of 2-3 runs and in windows of single letters up to 9; the joined string is flagged only when it EXACTLY equals a denied number word, vague word, ordinal or single-word directive verb (`f i v e`, `fi-ve`, `f.i.v.e`, `re-turn`) and not every piece is itself denied. `to day`, `to hear`, `no one`, `one-way` are unchanged (`one` stays strict through the ordinary scan and is not double-reported). A slot, comma or sentence end is a boundary, so slot fills never glue to neighbouring words. It applies in every number mode (including `digits`, where the final verifier cannot read a split number). Multi-word directive phrases ("take shelter", "you should") are not joined. The final `_speak` gate does not run this pass.
  - New PLACEHOLDERs: `generation.corrective_retry.hints.split_token_in_prose` ("Write every word whole; do not split a word with spaces, hyphens or dots, and write no numbers."); the `vague_quantity_in_prose` hint now also says "or an ordinal like fifth"; `render_system` tells the model to write words whole and avoid ordinals.
  - Tool-supplied accented place names (`Café`, `São Paulo`) pass the final gate untouched: the prose allowlist applies to model text only, covered by a handler test.
  - Residual risk: lexical scanning cannot be complete against adversarial spellings (other languages, phonetic spellings, longer splits, multi-word directive splits, number-adjacent phrasing). These checks target a small model's accidental or lazy output. The real backstop is the slot protocol (the model is shown no values and code fills every number) together with measuring the small model's actual behaviour on real runs; `first`/`second` ordinals are allowed on purpose.

Accepted risks / open questions (not resolved here):
- Finding 3, `digits` mode: the attribution prefix can lend false trust to a passage number attached to the wrong fact. The verifier only checks that the number appears somewhere in the retrieved passages, and the prefix then presents the sentence as the document's claim. Accepted for now; number-to-claim provenance (unit/claim binding, or `quote_span`) is an open question.
- Finding 5, the pronoun "one" ("which one") stays a number word and is rejected in prose, deliberately left strict pending measurement of how often it costs a real answer. A test pins this.
- The `map` filler (`Showing {place_name} on the map.`) omits the other required slots, so `postprocess` would reject it (pre-existing; the map turn is template-only and the shadow demo does not run it).
